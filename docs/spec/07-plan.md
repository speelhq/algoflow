# 07 — Plan

## Stack

| Concern         | Choice                                                             |
| --------------- | ------------------------------------------------------------------ |
| build, language | Vite, React, TypeScript 7 (the Go compiler; binary `tsc`), strict, pnpm |
| state           | Zustand                                                            |
| styling         | Tailwind CSS; tokens in `src/ui/theme.css`                         |
| primitives      | shadcn/ui generated on Base UI                                     |
| drag and drop   | dnd-kit                                                            |
| lint, format    | Oxlint with `oxlint-tsgolint` (`--type-aware --type-check`), Oxfmt |
| tests           | Vitest, Playwright                                                 |
| CI, hosting     | GitHub Actions, GitHub Pages                                       |

P-01 `src/lang`, `src/runtime`, `src/python` import no third-party package
(their `*.test.ts` files import Vitest only).

P-02 No graph, flow, diagram, or code-editor library is added; the chart
layout (U-30) is computed by `src/ui/chart/layout.ts` and drawn as SVG.

P-03 Dependencies are pinned at scaffold time to the latest stable release;
`typescript` and `oxlint-tsgolint` share a major version.

P-04 `src/ui/primitives/` holds components generated by `shadcn add` as
configured in `components.json` (`style: base-nova`, `css: src/ui/theme.css`,
`ui: @/ui/primitives`); generated files are not edited manually. `shadcn` is a
runtime dependency because `theme.css` imports `shadcn/tailwind.css`.

P-05 Panel resizing (U-03) is implemented with pointer events in
`src/ui/app/ResizeHandle.tsx`; no panel-resizing library is added.

P-06 `.oxlintrc.json` disables `react/react-in-jsx-scope` (automatic JSX
runtime), `jsx-a11y/prefer-tag-over-role` (an interactive `separator` has
no HTML element), `require-yield` (leaf block runners are generators with no
events), `unicorn/no-thenable` (the `if` statement's `then` region), and
`typescript/no-redundant-type-constituents` (spec types such as
`Id | "main"`), and disables `no-await-in-loop` under `e2e/` (sequential
Playwright assertions). `pnpm lint` passes with zero errors; warnings do not
cause it to fail.

P-07 `vite.config.ts` and `playwright.config.ts` read the base path from
`VITE_BASE` (default `/`); CI sets it to `/<repository name>/` so project
Pages resolve assets.

P-08 Files use LF line endings (`.gitattributes`), two-space indentation
(`.editorconfig`), and Oxfmt formatting; `.oxfmtrc.json` excludes `docs/`.

P-09 Playwright runs Chromium only, at 1440 × 900, against
`vite preview --port 4173` serving `dist/`; `scripts/*.ts` run with `tsx`.

## Process

P-10 `docs/` is tracked: the spec, `decisions.md`, and `design/`. `private/`
is ignored and holds only `PROMPTS.md`, the milestone prompts with the links
to the design canvases; nothing required by the code, the spec, or a review
resides there. A change to the spec is committed separately, before the code
that implements it.

P-11 `main` takes only rebase merges of pull requests whose CI passed. A
pull request is one or several vertical slices under approximately 600
changed lines; a milestone comprises several pull requests. Its body follows
`.github/pull_request_template.md`:
What, Why (spec ids and milestone), Verification (command output), Notes
(deviations, and the issue of every review finding it does not fix).

P-12 Open questions, known faults, and tasks reside in GitHub Issues, not in
the spec or in a file. Milestones `M-03`..`M-10` correspond to this file. An
issue that names a problem has one label: `decision` (the spec lacks an id;
closed by the pull request that records the id and its reason), `defect`
(behaviour contrary to an id), `debt` (one fact recorded in two places), or
`perf` (a cost to measure before changing); a task (a board to export, a file
to migrate) has a milestone and no label. A session starts with the issues of
its milestone and ends by filing every finding it did not resolve; a pull
request closes the issues it resolves by number.

P-13 `docs/design/` holds one PNG per board of the design canvases, under
the names `docs/design/README.md` lists with what each board shows and where
the spec deviates from it; the spec takes precedence over a board. A screen the spec
describes and no board shows is an issue labelled `decision` under the
milestone that builds it.

P-14 The state of the work is not recorded in a file: the open milestone, its
issues, and the open pull requests determine what is next; the spec states
what must be and the code what is. No handoff file is retained between
sessions. Working knowledge that neither the spec nor the code holds (tool
behaviour, test conventions) resides in `CLAUDE.md`.

## Milestones

Each milestone is a vertical slice with an exit criterion; a milestone
closes only when every listed test passes.

M-00 **Scaffold.** Stack, CI, `src/i18n` with `en.json` and `t()`, a
resizable shell. Exit: `lint`, `test`, `build` pass; a Playwright test
asserts the panel titles.

M-01 **Language and runtime, no UI.** `02-language.md` complete; blocks of the basic
and control categories plus `call` and `return` (`03-nodes.md`); `04-runtime.md`
interpreter R-01..R-10, emitter E-01..E-06, parser G-01..05; `scripts/check.ts`;
the first five course problems with recorded expectations. Exit: T-01/02/03/04/05
for included blocks; T-06 for those problems.

M-02 **Playback.** Driver R-11/12, the shared judge (C-10..C-12, C-15),
challenge bundling (C-14). Exit: T-05 for R-11/12; T-06.

M-03 **Problem pages, read-only.** Routes and pages U-01..U-06 (Playground
and Modules pages are stubs until M-04 and M-07); Problems page U-10..U-14
with `plans.json` (C-16) and progress (C-17); the panel U-20..U-25 with the
solution shown in the chart region (U-22) without `Load into my chart`;
chart rendering U-30..U-33, U-38, U-39 with N-09 `chart` fields, the path
bar holding `main` alone, and Input nodes listing the cases without
`Custom…`; run mode U-60..U-65 on the pre-running driver (R-11, R-12) with
