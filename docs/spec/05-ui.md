# 05 — UI

All labels below are `en.json` texts. `ja.json` holds the same keys with
Japanese texts from M-10 (U-71).

## Pages

U-01 The application has six pages, addressed by hash routes: Problems
(`#/`), Problem (`#/p/<id>`), Playground (`#/play`, U-15), Playground
program (`#/play/<id>`), Modules (`#/modules`, D-07), and Module
(`#/m/<name>`, D-08). A Playground program is the Problem page without the
`Problem` tab, the Input nodes, and Submit (S-07); its top bar has an
editable title and `Export` (L-53) in place of the problem title and
`Submit`.

U-02 Problems page: a 52 px header with the app name, the tabs `Problems`,
`Playground`, and `Modules`, Help, and the JA/EN switch; below it one
section per study plan and `More problems` (U-12). The Playground and
Modules pages share the header.

U-03 Problem page: a 52 px top bar with `← Problems`, the title, `▶ Run`,
`✓ Submit`, undo, redo, and `⋯` (U-05), and below it two regions: the panel
(U-20) on the left, 320 px by default, resizable from 280 px to 50 % of the
viewport width, collapsible (U-24), its width persisted under
`algoflow:layout`; and the chart region, which holds from top to bottom the
path bar (U-30), the chart, and, while running, the transport (U-60). There
is no third region.

U-04 Help, opened from `⋯` (U-05) or the header's `?` (U-02), is a dialog
with the keyboard table below and three lines describing the loop (build
the chart, run it on one input, submit); texts under `app.help.*`, no
external links.

U-05 `⋯` opens a menu: `Open in Playground`, which creates a Playground
program from the current program, each input becoming an assignment at the
top of `main` (the E-03 form), and opens it; `Start over`, which replaces
the program with an empty `main` as one undoable edit (L-50 `resetProgram`);
and `Help` (U-04).

U-06 Every page sets the browser tab title to `<title> — AlgoFlow`, where
`<title>` is the problem's or Playground program's title, the module's
title or name (D-01), or the page name.

## Problems page

U-10 A problem row shows a status mark (`✓` solved, `•` attempted, blank),
the title, the difficulty (`Easy`, `Medium`, `Hard`), and the topic tags; a
row opens the Problem page.

U-12 The page shows one section per plan in C-16 order: the title, the
one-line description, `n of m solved`, `Continue` (the first unsolved
problem) or `Start`, and the plan's rows in plan order; a last section
`More problems` holds the problems in no plan, ordered by title. There are
no filters and no overall progress meter.

U-13 Per-problem progress (C-17) drives the status marks and the plan
counts.

U-14 Topics are fixed: `Output`, `Variables`, `Loops`, `Conditions`,
`Lists`, `Searching`, `Sorting`, `Recursion`, `Dictionaries`, `Classes`,
`Gradients` (`problems.topic.<key>`); they appear as tags on rows (U-10)
and in the `Problem` tab (U-21).

## Playground page

U-15 One row per Playground program (title, last edited), ordered by last
edit; `New` opens an empty program, `Import…` (L-53) adds one from a file,
and each row has `Delete`, which asks.

## Panel

U-20 The panel has the tabs `Problem`, `Result`, and `Python` on a Problem
page, and `Result` and `Python` on a Playground program and a Module page.
A page opens on its first tab; `Run`, `Submit`, and `Test` (D-20) select
`Result`; nothing selects `Python` or returns to `Problem` by itself.

U-21 Tab `Problem`: the title, the difficulty, and the topic tags; the
statement (markdown); `Example` (the first test's inputs and its expected
output, one line per value, an output of more than eight lines folding to
its first five and `… n more`); `Cases used by Submit` (the inputs of every
test); a `Hints` section revealing one hint per click on `Show next hint`
and showing `n of 3 shown`, the number being recorded (C-17); and a
`Solution` row with `Show solution` (U-22).

U-22 `Show solution` shows the solution in the chart region, read-only,
under a band `Solution` with `Load into my chart`, which replaces the
program with the solution as one undoable edit (L-52), and
`Back to my chart`; showing it is recorded (C-17).

U-23 Tab `Result` shows, for one case: the case selector, which holds the
same choice as the Input nodes (U-32); the variables of the shown frame
(U-68) with one view each (V-01..V-06); `Output`, the lines printed so far;
beside it `Expected`, when the case is one of the challenge's tests and
expects `stdout`, the two aligned line by line with a blank cell where one
side has no line; every expected variable as a row with its value, or a
blank when the program never created it, beside its expected value; and,
when the run ends on such a case, that case's verdict (C-15) with the first
output row that differs, or else the first variable row that differs,
marked. After a submission the tab adds what U-81..U-85 state. A `Custom…`
case shows no `Expected`, and a Playground program has no case selector and
no `Expected`. Before any run the tab shows the case selector, the chosen
case's `Expected`, and `result.empty` (`Run to see the values`).

U-24 The panel collapses to a 40 px rail from a toggle in its header; the
state persists under `algoflow:layout`.

U-25 Tab `Python` shows the emitted code with line numbers (E-01):
keywords, strings, numbers, and comments are coloured and nothing else;
hovering a line outlines its node, selecting a node highlights its lines,
clicking a line selects its node and, for a line inside a function, shows
that function's chart (U-30); while running, the line of the current
statement is highlighted. `Copy` and a `.py` download act on the shown
file. When the program uses modules a file row switches among `main.py`
and one `<name>.py` per module (E-09); in a program's tab a module's file
is read-only, has no node interaction, and carries `Open module <name>`
(D-18), while on a Module page the module's file is the shown file with
the full node interaction. Python text appears nowhere else.

## Chart

U-30 The chart is a flowchart laid out top-down by the application; nodes
are never placed by hand and edges are never drawn by hand (P-02). The
chart region shows one chart at a time: `main`, one function, or one class
(its field table, N-06). Above it the path bar is always present: a `▾`
button listing `main`, every function, and every class of the program,
then `Add function` and `Add class` (M-06), with a red dot on the button
and on each listed chart that holds a diagnostic and is not shown; and the
path, one segment per chart, reading `main`, `name(params)` for a
function, or the class name. In build mode the path is the trail of
`Open <name>` (U-41): opening appends a segment, clicking an earlier
segment returns to that chart with the call node that was opened selected,
and choosing from `▾` resets the path to that one chart. U-68 states the
path while running.

U-31 The main chart shows, in order: the `Start` terminal, one Input node
per input (`Input n = 15`, challenges only), the statements of `main`, and
the `End` terminal; a function chart shows `Start name(params)`, its body,
and `End`. Edges are vertical with arrowheads; a `Return` node's edge leads
to `End`. Clicking `Start name(params)` opens the function's editor: the
name, the ordered parameters with add and remove, `Delete function`, and
`Move to module…` (D-09); a class's field table carries the same name
field, `Delete class`, and `Move to module…` in its header.

U-32 Clicking an Input node opens a menu of the problem's cases (`n = 15`,
`n = 1`, …) and `Custom…` (M-04), which opens the value editor of U-50
limited to literals (numbers, texts, `true`, `false`, `none`, lists, and
dicts; no variables, operators, or calls) and stores the result as `Data`;
Run uses the chosen values. Choosing a case sets every Input
node to that case's values; once any Input node holds a `Custom…` value
the case selector (U-23) reads `Custom…`.

U-33 Node shapes come from the block's `chart` field (N-09):

| `chart`  | Rendering                                                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| absent   | a rounded box with the block's sentence (N-02)                                                                                                                                                                            |
| `branch` | a diamond with the condition; the `yes` region to the right joined by a `Yes` edge, the `no` region below joined by a `No` edge, both merging below; an empty `no` region is a bare `No` edge                            |
| `check`  | a diamond with the condition; `Yes` leads down into the body, whose last node returns by a back edge to a junction above the diamond; `No` leads on past the loop                                                        |
| `counted`| three generated nodes around the body: `Set i to start`, the diamond `Is i < stop?`, and `Set i to i + 1` (texts `node.<key>.init/check/step`, N-09), drawn grey; the body and the back edge as for `check`             |

A `branch` or `check` diamond asks its condition as a question: the
question of the U-50 template it matches (`chart.question.<name>`: `Is i
divisible by 15?`, `Does a equal b?`), else `Is <chips>?`
(`chart.condition`). A block with `requires: "function"` has no edge to
the next node: its edge leads to `End` (U-31) and carries the connector
after it (U-34). A block with `requires: "loop"` is drawn as any other box.

Generated nodes are not selectable on their own: clicking one selects the
loop node, whose editor holds the variable and bounds. The slots drawn on
a generated node are the loop's slots, so clicking the start value on
`Set i to 0` opens the loop's editor on that slot (U-41).

U-34 A `+` connector sits on every edge: before the first node and after
the last node of every region, between nodes, and on an empty `Yes`, `No`,
or body region. Clicking it opens the block menu (U-40) and inserts the
chosen block at that edge. While `main` has no statement its one connector
is labelled `Add your first block`.

U-35 Click selects one node; Delete and Backspace remove it (a loop or
branch with its regions); Ctrl/Cmd+D duplicates it; Esc closes the editor
and clears the selection.

U-36 A node can be dragged onto another `+` connector, within or across
regions; a drop producing `E_BREAK_OUTSIDE` or `E_RETURN_OUTSIDE` is
refused with a tooltip.

U-37 A node with a diagnostic shows a red dot; hovering shows the message
and, when `fix` is set, a button applying it, and the node's editor (U-41)
shows the same message and button at its top. `E_EMPTY_SLOT` shows no dot:
the empty slot's placeholder (U-51) is its only mark.

U-38 The chart fits its width on open and scrolls vertically; `−`, `100%`,
and `+` controls in the chart's corner zoom it.

U-39 The chart highlights the statement containing an event's `nodeId`
(expressions have no node of their own); an error highlights the statement
containing the failing node.

## Block menu and node editor

U-40 The block menu lists the registered statement blocks (N-01 `shape:
"stmt"`, the method statements of N-04, not `hidden`) with a search over
`label` and `help`, grouped in the category order of N-01 (`Basic`,
`Control`, `List`, `Function`, `Dict`, `Class`, `Math`), each category in a
fixed order that puts `assign`, `print`, `if`, `for`, and `while` first in
theirs; a block whose `requires` the connector does not meet is listed
disabled with the reason (`menu.requires.loop`, `menu.requires.function`).
The `Function` category ends with `New function…`, which asks for a name,
creates the function, and inserts a call to it. Then come the program's own
functions under `This program`, when it has any, and a last row `Modules ▸`
opening one group per module (D-03) titled by its name or title, learner
modules before built-in ones, each listing its functions as calls. Choosing
an item inserts it and opens its editor. Expression blocks are not in this
menu; slots offer them (U-52).

U-41 The node editor is a popover anchored to the selected node; clicking
a slot drawn on the node opens the editor with that slot's menu open. It
shows the block's sentence with its slots editable in place: `id` slots are
text inputs limited to L-01 with a suggestion row that lists, in order, the
names in the challenge's `expect.variables` (marked as asked for by the
problem), the names already in the program, and
`i j n tmp low high mid found count total`; `expr` slots per U-50; `exprs`
slots are ordered lists with add and remove; `text` slots are inputs;
`body` slots are not shown. Below: `node.<key>.help`; a footer with
`Duplicate`, `Delete`, and, when the node calls a function or constructs a
class, `Open <name>`, which shows that function's or class's chart (U-30)
or, for a module's, opens its Module page (D-18).

U-42 A loop's editor edits the variable and the bounds (`for`), the list
(`foreach`), or the condition (`while`); the generated nodes (U-33) follow.

## Expressions

U-50 An `expr` slot's menu opens with one field that accepts what is
typed: digits make a number, a leading quote makes a text, and letters
filter every item below it. Under the field comes a template row. For a
condition slot (`if`, `while`) the templates are:

| Template                     | Expression        |
| ---------------------------- | ----------------- |
| `□ is divisible by □`        | `a % b == 0`      |
| `□ equals □`                 | `a == b`          |
| `□ does not equal □`         | `a != b`          |
| `□ is greater than □`        | `a > b`           |
| `□ is less than □`           | `a < b`           |
| `□ is at least □`            | `a >= b`          |
| `□ is at most □`             | `a <= b`          |
| `□ is in □`                  | `a in b`          |
| `Build my own…`              | the chip editor   |

For a value slot the row offers the visible variables, a number, a text,
`true`, `false`, and `Build my own…`. A statement's slot holding an
expression that matches a template shows the template's sentence
(`editor.template.<name>`), the first match in table order; any other
expression is shown as chips, and the chips inside an expression keep
their symbols (`a < b and b < c`).

U-51 The chip editor renders an `Expr` as nested chips; an empty required
slot renders as a dashed `choose a value`, on the node and in the editor.

U-52 Below the template row, and for every chip, the menu has these groups
in order:

| Group     | Items                                                        |
| --------- | ------------------------------------------------------------ |
| Variables | variables visible at this node, most recently assigned first |
| Values    | number input, text input, true, false, none                  |
| List      | `[…]`, `item {i} of {a}`, `length of {a}`                    |
| Math      | `+ − × ÷ // % **`                                            |
| Compare   | `== != < <= > >=`, `in`                                      |
| Logic     | `and or not`                                                 |
| Call      | builtins, user functions, module functions, methods, `new …` |

U-53 An operator wraps the current chip as its left operand and focuses
the new right slot; a list operation wraps the current chip as the list; a
variable or literal replaces the chip.

U-54 A chip's context menu offers `Delete` and, for a `binop`, `Unwrap`
(replaces the binop with its left operand).

U-55 Every expression slot has a `Type as text` toggle: the text is parsed
on blur or Enter (G-01); a parse error underlines from `position` and keeps
the previous expression; toggling back shows chips.

## Running

U-60 `Run` with diagnostics present does not start: it shows the chart of
the first node with a diagnostic, selects that node, and shows its message
(U-37); `Submit` does the same. Otherwise `Run` pre-runs the program (R-11)
with the Input nodes' values and puts the page in run mode: editing is
disabled, the top bar shows `Running with n = 15` and `■ Stop`, and the
transport is docked under the chart: `Back`, `Pause` / `Play`, `Step`,
`Step over` (R-17), `Skip` (R-19), the position bar `step k of N`, which
can be dragged to any step (R-11 Seek), and the speed slider 1–50. Playback
starts playing at the remembered speed (3 at first, persisted under
`algoflow:layout`); `▶ Watch this case` (U-81) starts paused. A run whose
pre-run ends in `E_STEP_LIMIT` says so (`run.endless`) before playback.
`Stop` returns to build mode; once the run has ended, in `done` or `error`,
clicking a node also returns to build mode and opens that node's editor.
Before that, clicking a node sets the breakpoint on it (R-19), pausing
first when the run is playing; clicking the node that holds it, or Esc,
clears it. The node shows a breakpoint mark (`run.breakpoint`), and the run
pauses each time it arrives there; `Skip` goes on without drawing the steps
between to the next arrival, or to the end of the run when no breakpoint is
set.

U-61 While running, the edges and nodes of the current pass are drawn in
the taken-path colour, the current node has the accent outline and is
scrolled into view, and a diamond shows `✓` or `✗` after its check (from
its `compare`, or from the `loop` event of a generated check), cleared when
the diamond is entered again and when a loop containing it starts a new
pass (its `loop` event clears every diamond in its body).

U-62 No variable's value is drawn on the chart: the values of the moment
are in the narration (U-63), every variable is in the `Result` tab (U-23),
and the call stack is the path bar (U-68).

U-63 A narration tooltip sits beside the current node and describes the
last event in one sentence (`run.narrate.*`): `enter` → `Checking i is
divisible by 3` for a condition and the block's sentence otherwise; `read`
→ `Read item 2 of nums: 5`; `compare` → `"3 is divisible by 15" is false,
so No`, the sentence of the U-50 template the comparison matches with the
values of the moment (`"5 is greater than 3" is true, so Yes`); `write` → `i is now
3`; `swap` → `Swapped items 1 and 2 of nums`; `loop` → `Pass 3: i is 3`;
`print` → `Printed "Fizz"`; `call` → `Calling f(2)`; `return` → `f returned
4`, which alone narrates a module call (R-11); the end of the run →
`Finished in 124 steps`; an error → the message (U-70). Values are written
as the blocks write them: `true`, `false`, `none`, a text in quotes. A
`compare` takes its values from the event's operands when the template's
blanks are the compared operands, from the shown frame for `is divisible
by`, and says `so Yes` / `so No` only when it is a diamond's whole
condition. A `read` of several items → `Read 3 items of nums`; a `loop`
without a variable → `Pass 3`; a list no variable of the frame holds is
`a list` (`run.narrate.ref.*`).

U-65 A runtime error outlines the failing node in the error colour, shows
the message (U-70) beside it, stops the transport, and leaves the path bar
on the failing frame's stack; an error inside a module function is shown on
the node that called it, whose `Open <name>` carries that call's arguments
(D-18).

U-68 While running, the path bar is the call stack: `main` first, one
segment per frame, the last one running; the chart shows the running
frame and follows it on every `call` and `return`, and Back and Seek show
the frame of the step they reach. A module function's frame is never a
segment: its call is one step (R-16). A segment reads `name(args)` with
numbers, texts, and booleans shown and any other argument as `…`, adjacent
ones merged; beyond `main` and the last three segments the middle folds to
`… n`, which lists them on click. While paused, clicking a segment shows
that frame's chart with the call it waits on marked and that frame's
variables in `Result` (U-23); the next step follows the running frame
again. While playing, the click pauses first.

## Submission

U-80 `Submit` judges every test on its own runner (C-10..C-12, C-15),
records the attempt (C-17), and selects the `Result` tab.

U-81 A failed submission shows `Wrong Answer`, `k of n cases passed`, one
chip per case (`✓`/`✗`, the first failing one selected), and for the
selected case the rows of U-23 with the first differing one marked, and
`▶ Watch this case`, which sets the Input nodes to that case and starts a
run paused at the first difference (R-11 Seek): the step of the `print`
that produced the first differing line, or the last step of the run when
no `print` produced it or a variable differs. The narration there says
which (`run.narrate.difference`: `This printed line 1`, said at that step in
place of the event's sentence;
`The run ended here`); the position bar leads back to step 0.

U-82 A wrong answer is shown as its rows and nothing else: no sentence is
generated about the difference, and no node is marked on the chart; only a
runtime error marks a node (U-65). `Hint` names the three authored hints of
a challenge (C-22) and nothing generated.

U-83 An accepted submission shows `Accepted`, one `✓` chip per case, the
steps and loops of the first case, `What you used` (the challenge's
`takeaway`, C-01), `Move to module <name>` when the challenge names a
module (C-19) and the program has a function or class (the D-09 operation),
`See your program as Python`, which selects the `Python` tab, `Compare with
the solution` (U-22), `Open in Playground` (U-05), and `Next problem →`
(the next unsolved problem of the current plan, else the next row of its
section) or, after the last problem of a plan, `Plan complete` with `Back
to Problems`; the problem becomes solved (C-17).

U-84 A test that ends in a runtime error shows its message (U-70) in place
of `Output`.

U-85 A submission in which a name listed in `defines` (C-21) resolves to
a built-in module shows, in place of a verdict, `{name} comes from the
built-in module {module}. Build it in this program, or Clone the module
and build it there.` (`result.builtin`), and records nothing.

## Views

V-01 The `Result` tab chooses one view per variable by value:

| Value                       | View                                       |
| --------------------------- | ------------------------------------------ |
| int, float, str, bool, none | inline text                                |
| list of lists ≤ 30 × 30     | grid                                       |
| list of ≤ 40 values         | cards, each value as inline text           |
| list of 41–100 numbers      | bars                                       |
| other list                  | summary: `length N`, first five, last five |
| dict ≤ 50 entries           | key/value table                            |
| larger dict                 | summary                                    |
| obj                         | object card: class name and fields         |

V-02 When any variable of the shown frame references an object, the tab
also shows one graph of all objects reachable from the frame: one card per
object (class name, scalar fields), one edge per reference-valued field or
list element, laid out top-down by longest path from the roots. Above 200
objects, the graph shows objects touched by the last 20 events and
`N objects`.

V-03 Refs of `lastEvent` are highlighted for 300 ms: `read` blue,
`write` orange. A `swap` slides the two bars or cards past each other in
200 ms; a `write` changes a bar or card without a transition.

V-04 Bars label indices when ≤ 40 items; heights share one scale per
list; negatives draw below the axis.

V-05 Views are drawn with CSS transforms keyed by index and re-render only
the variables changed by the last event.

V-06 The learner may switch a list variable's view among `cards`, `bars`,
`grid` (lists of lists only), and `tree`; the choice persists under
`localStorage` `algoflow:views` keyed by the program's storage key (L-53)
and the variable name. `tree` draws item `i` as a node whose children are
items `2i + 1` and `2i + 2`, laid out top-down by level, each node showing
its index and the item as inline text.

texts (e.g. the loanword for "loop" beside the everyday word).
